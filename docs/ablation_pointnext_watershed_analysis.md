# PointNeXt-L 实例分割消融实验：模块贡献机理分析

> 语义 backbone：PointNeXt-L ｜ 实例聚类：Watershed-3D ｜ 数据集：test 集（14 块田间点云，224 个真实实例）｜ 随机种子固定

## 1. 实验设计与模块分解

本组消融实验以 **PointNeXt-L 语义分割 + Watershed-3D 实例聚类** 为骨架，仅变换后处理模块，逐级拆解各模块的独立贡献。完整实例分割管线为：

```
语义分割 → Watershed-3D 聚类（初始分簇）→ GIDM 骨架切割（拆分粘连株）→ 碎片回并 merge_back（合并过分割碎片）→ 后过滤
```

其中 GIDM（Geometric Instance Density Modeling）是核心贡献，内部由两个方向相反、职责互补的机制构成：

- **骨架切割（skeleton cut）**：沿簇的主轴投影，检测密度波谷，对粘连多株簇进行递归切割，属于**拆分**操作，目标是抑制**欠分割**（under-segmentation）。
- **碎片回并（merge back）**：对切割后主轴跨距小于阈值的碎片，按质心距离 + 主轴夹角约束回并至相邻大簇，属于**合并**操作，目标是抑制**过分割**（over-segmentation）。

两个机制共同构成"先拆后合"的几何闭环，理论上应在抑制欠分割与过分割之间取得平衡。

### 消融配置说明

| 配置 | 语义分割 | Watershed 聚类 | GIDM 骨架切割 | 碎片回并 merge_back |
|---|---|---|---|---|
| base（无后处理） | ✓ | ✓ | ✗ | ✗ |
| 全模块（最优合并） | ✓ | ✓ | ✓ | ✓ |
| noMB（最优合并但关回并） | ✓ | ✓ | ✓ | ✗ |

> 最优合并参数：`merge_min_diameter = 0.50 m`，`merge_max_dist = 0.30 m`。

## 2. 消融结果

| 配置 | Instance Precision | Instance Recall | Instance F1-score | Instance mIoU | Semantic mIoU | MAE(Count) |
|---|---|---|---|---|---|---|
| base（无后处理） | 0.675 | 0.487 | 0.562 | 0.704 | 0.845 | 5.07 |
| 全模块（最优合并） | 0.820 | 0.868 | 0.840 | 0.751 | 0.845 | 1.50 |
| noMB（最优合并但关回并） | 0.799 | 0.884 | 0.838 | 0.751 | 0.845 | 1.93 |

## 3. 机理分析

### 3.1 base → 全模块：骨架切割补足了 Watershed 的欠分割缺陷

从 base 到全模块，最显著的变化是 **Recall 从 0.487 跃升至 0.868（+0.381）**，同时 **MAE 从 5.07 骤降至 1.50（-3.57）**。

**机理**：base 阶段仅有 Watershed-3D 聚类，其种子间距 `min_seed_distance = 0.30 m` 决定了初始分簇的最小尺度。对于闭冠甘蓝中紧密贴合的相邻植株，点云密度在株间间隙处并不形成足够深的波谷，导致 EDT（欧氏距离变换）峰检测无法为每一株生成独立种子——**多株被归入同一个大簇**。这直接表现为：

- Recall 极低（0.487）：超过一半的真实植株未被单独识别；
- MAE 高达 5.07：平均每块田地数错约 5 株。

骨架切割正是针对这一缺陷设计的：把每个簇沿**主轴方向投影到一维**，统计各切片的密度分布，检测**密度波谷**作为切割位置，对粘连多株簇进行递归切割。这一操作把粘连的大簇"拆开"，使每株获得独立标签，因此 Recall 大幅回升、计数误差大幅下降。

**关键证据**：MAE 下降幅度（-3.57）远大于 Precision 的增幅（+0.145），说明骨架切割的**主要收益是"找回漏检的植株"（抑制欠分割）**，而非"提高匹配精度"。

### 3.2 全模块 vs noMB：碎片回并的真实作用是"计数校正"

对比全模块与 noMB（其余全同，仅关掉碎片回并）：

- **F1 几乎不变**（0.840 vs 0.838，差 0.002）
- **Precision 略降**（0.820 → 0.799）
- **Recall 略升**（0.868 → 0.884）
- **MAE 明显变差**（1.50 → 1.93，+0.43）

**机理**：碎片回并处理的是骨架切割的"副作用"——过分割。骨架切割在拆分粘连株时，若切割面恰好落入稀疏的叶片间隙，会产生一些**主轴跨距很短的小碎片**（本应属于母株，却被切成了独立小块）。这些碎片会导致：

1. **Precision 下降**：预测实例数虚高，多出的小碎片无法与任何真实植株匹配（多算）；
2. **MAE 上升**：株数被多计。

碎片回并的作用就是把这些小碎片**重新并回母株**，因此：

- **开回并（全模块）**：碎片被吸收，Precision 恢复至 0.820，MAE 降至 1.50（计数更准）；
- **关回并（noMB）**：碎片残留，Precision 掉到 0.799，MAE 升到 1.93。

**为什么 F1 几乎不变？** 因为 F1 是 Precision 与 Recall 的调和平均，而这里 Precision 下降与 Recall 上升**相互抵消**——关回并后多出的碎片既不是正确的匹配，也几乎不影响大簇的 Recall（大簇的匹配早已建立）。这揭示了一个重要规律：

> **碎片回并主要影响"计数"（MAE）和"预测纯度"（Precision），而非"匹配好坏"（F1）**——它承担的是闭环中的"计数校正"角色。

### 3.3 Semantic mIoU 恒为 0.845：后处理与语义解耦

三组配置的 Semantic mIoU **完全一致**（均为 0.845）。这是关键的结构性证据：所有后处理模块（骨架切割、碎片回并）都**只操作实例标签的划分**（把一个语义为"甘蓝"的点集拆成若干实例、或把若干实例合并），**从不改变单个点的语义类别**。因此语义分割质量在后处理前后保持不变。

这反过来证明了实验的**变量隔离是干净的**：三组数据的差异完全来自实例后处理模块，而非语义分割的波动。

## 4. 总结：三个模块各司其职

| 模块 | 主要职责 | 关键指标表现 |
|---|---|---|
| Watershed-3D 聚类 | 初始分簇 | 提供粗粒度分簇，但粘连株欠分割（Recall 仅 0.487） |
| GIDM 骨架切割 | 拆分粘连株（抑制欠分割） | Recall +0.381，MAE -3.57 |
| merge_back 碎片回并 | 回并过分割碎片（抑制过分割） | Precision +0.021，MAE -0.43（计数校正） |

三者共同构成"先粗分簇 → 再拆粘连 → 后合碎片"的完整闭环：**骨架切割负责"找回漏检"，碎片回并负责"纠正多算"**，二者一拆一合，方向相反但目标一致——在抑制欠分割与过分割之间取得平衡，最终将 F1 从 0.562 提升至 0.840、计数误差从 5.07 降至 1.50。

## 5. 关键结论

1. **骨架切割是实例分割增益的绝对主体**（F1 +0.278，Recall +0.381，MAE -3.57），本质是弥补 Watershed-3D 在粘连植株上的欠分割缺陷。
2. **碎片回并的价值在于"计数校正"而非"匹配提升"**：F1 增益有限（+0.002），但 MAE 显著改善（-0.43）。
3. **Semantic mIoU 三组恒等**，证明后处理只改变实例划分、不触碰语义类别，实验变量隔离干净。
