# 粘连植株簇分割：基线模型 vs ADPV（Ours）

## 数据说明

从 `测试/output_RandLA-Net` 与 `测试/output_pointgroup` 的中间步骤结果中，提取 3 种粘连程度（3/4/5 颗植株粘连）的场景进行对比：

- **GT（真实标签）**：`测试/{场景}.ply` 中的 `scalar_Instance_ID` 字段。
- **基线模型（无 GIDM）**：
  - RandLA-Net：`step4_cluster_coarse.ply`（基础聚类，无 GIDM）；
  - PointGroup：`step3.5_pointgroup_proposal.ply`（offset 提案 + NMS，未补全）。
- **ADPV（Ours）**：`step5_final.ply`（含 GIDM 骨架切割 + 碎片回并 + 后处理）。
- **指标**：实例级 F1（IoU ≥ 0.5 一对一匹配）。

> 每个粘连等级当前仅 1 个场景样本（共 6 组 backbone×场景组合）。
> PointGroup 的基线采用其"原生"的 offset 提案输出（step3.5），以真实反映提案机制在粘连场景下的固有缺陷，而非经过未分配点补全后的结果。

### 解读

1. **RandLA-Net 基线严重欠分割**：纯语义 + Watershed 聚类在粘连场景下难以分离植株，5 颗粘连时基线仅分出 2 个大簇（F1 = 0.000）。ADPV 将 F1 提升至 0.889，修正效果显著。
2. **PointGroup 提案在重度粘连下失效**：3 颗粘连时提案尚能分出 2 株（漏 1），4 颗时正确；但 5 颗重度粘连时 offset 提案完全失效（proposal 阶段 0 株，F1 = 0.000，100% 点未分配），需依赖后续补全 + ADPV 才恢复至 F1 = 1.000。
3. **结论**：ADPV 的价值主要体现在**粘连程度高、上游提案/聚类失效**的场景，作为几何后处理弥补基础方法的欠分割缺陷。重度粘连（5 颗）下 ADPV 对 RandLA-Net 和 PointGroup 的欠分割修正率分别达 80.0% 与 100.0%。

---

### 机理分析：5 颗粘连时 RandLA-Net 基线 F1 为何为 0

5 颗粘连场景（`cloudR6`）中，RandLA-Net 基线（Watershed 聚类）只分出 **2 个大簇**，而真实有 5 株。这 2 个大簇各自合并了 2~3 株植株，导致它们与任何单株 GT 的 IoU 均低于 0.5 的匹配阈值：

| 预测簇 | 覆盖的真实植株 | 与各真实株的最高 IoU |
|:---:|:---|:---:|
| 簇 1（19,221 点） | 株9 + 株10 + 株11 | 株9 = 0.439，株10 = 0.481，株11 = 0.000 |
| 簇 2（20,445 点） | 株7 + 株8 + 株9 | 株7 = 0.423，株8 = 0.462，株9 = 0.042 |

由于实例匹配采用 **IoU ≥ 0.5** 的一对一标准：

- 簇 1 的最高 IoU = 0.481 < 0.5 → 无法匹配任何单株；
- 簇 2 的最高 IoU = 0.462 < 0.5 → 同样无法匹配。

因此 **TP = 0**，Precision = 0/2 = 0，Recall = 0/5 = 0，F1 = 0。

**本质**：不是"没有检测到植株"，而是**欠分割过于严重**——5 株被合并成 2 个"多株簇"，每个簇都因包含多余植株而使 IoU 被拉低到阈值之下，最终在严格匹配标准下全部失配。这恰好说明 ADPV（GIDM 骨架切割）的作用：它沿密度波谷切开这些合并簇、恢复正确的植株边界，使 F1 从 0 提升至 0.889。

**粘连程度与基线 F1 的对应关系**：

| 粘连等级 | 基线预测簇 | 匹配情况 | 基线 F1 |
|:---:|:---:|:---:|:---:|
| 3 颗 | 1 簇 | 簇含 1 株，IoU≥0.5 | 0.500 |
| 4 颗 | 2 簇 | 每簇含 2 株，与某单株 IoU≥0.5 | 0.667 |
| 5 颗 | 2 簇 | 每簇含 2~3 株，最高 IoU 均 <0.5 | 0.000 |

粘连越严重，单簇合并的植株越多，与 GT 单株的 IoU 越难跨过 0.5 阈值，最终在 5 颗时全部失配、F1 归零。

---

### 重要说明：过分割修正率为 N/A

在这 3/4/5 颗粘连场景中，**基线模型（无论 RandLA-Net 还是 PointGroup）的误差模式仅有"欠分割"（相邻株粘连未分离），不存在"过分割"（单株被错误拆分）**。

证据：所有场景的基线精确率（Precision）均接近 1.0（无虚检碎片），而召回率（Recall）因漏检而偏低。

因此：

- **过分割修正率无法用当前粘连场景计算**（基线无过分割需要修正）。
- 过分割现象出现在**稀疏点云**等其它场景（见 `docs/density_sensitivity_CN.md`），需另用稀疏密度数据评估 ADPV 的碎片回并（merge-back）修正能力。
